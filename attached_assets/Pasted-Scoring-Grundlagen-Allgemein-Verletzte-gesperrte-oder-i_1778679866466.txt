Scoring-Grundlagen:

Allgemein:

Verletzte, gesperrte oder inaktive Spieler dürfen keine guten Primärvorschläge sein.
Fehlende Profildaten sollen als Warning erscheinen.
Score soll nachvollziehbar sein.
Gründe müssen für Trainer verständlich formuliert sein.
Keine erfundenen Daten verwenden.
Nur vorhandene Spielerfelder nutzen.

Delivery:

dominantFoot berücksichtigen, wenn aus Rolle/SetPiece eine Seite ableitbar ist.
set_piece_specialist oder delivery_specialist stark positiv.
Aktiver Status positiv.
Fehlender Fuss oder fehlendes Spezialisten-Tag als Warning, nicht als harter Fehler.

Aerial Target:

headingStrength stark gewichten.
height positiv gewichten.
strong_header, best_header, far_post_target positiv.
Kleine Spieler oder niedrige Heading-Werte als Review/Warning.

Blocker:

height, headingStrength, strong_blocker positiv.
Körperlich passende Spieler bevorzugen.

Runner:

speed, fast, fast_runner positiv.
Sehr langsame Spieler als Review/Warning.

Rebound:

rebound_hunter positiv.
midfielder oder forward positiv.
Speed leicht positiv.

Rest Defense:

speed stark positiv.
defender oder midfielder positiv.
Aktiver Status wichtig.
Langsame Spieler als Risiko markieren.

Defensive Marker:

defender positiv.
headingStrength und height positiv.
goalkeeper normalerweise nicht vorschlagen.

Counter Outlet:

speed, fast, forward positiv.

Generic:

Aktive Spieler neutral bewerten.
Vorhandene passende Tags leicht positiv berücksichtigen.

Severity:

good: Score stark, keine kritischen Warnungen.
review: brauchbar, aber Coach sollte prüfen.
problem: verletzt/inaktiv, sehr tiefer Score oder unpassend.

Confidence:

Niedriger, wenn viele Profildaten fehlen.
Höher, wenn mehrere passende Felder vorhanden sind.

PHASE 3 — MATCHDAY ASSIGNMENT SUGGESTIONS API
────────────────────────

Erweitere artifacts/api-server/src/routes/matchdays.ts um einen neuen Endpoint:

POST /teams/:teamId/matchdays/:matchdayId/assignment-suggestions

Request Body:

{
  starterPlayerIds: string[];
  benchPlayerIds?: string[];
  setPieceIds?: string[];
  mode?: 'fill_empty' | 'replace_weak' | 'replace_all';
}

Default:

mode = 'fill_empty'

Logik:

Prüfe Teamzugriff mit vorhandener Auth-/Access-Logik.
Lade den Matchday.
Lade alle mit dem Matchday verknüpften Set Pieces.
Wenn setPieceIds mitgegeben werden, analysiere nur diese.
Lade alle Rollen dieser Set Pieces.
Lade bestehende Role Assignments.
Lade Spieler aus starterPlayerIds und benchPlayerIds.
Primäre Vorschläge bevorzugt aus Startelf.
Backup-Vorschläge bevorzugt aus Bank.
Spieler mit Status verletzt/gesperrt/inaktiv nicht als gute Primärvorschläge behandeln.
In fill_empty bestehende Assignments nie überschreiben.
In replace_weak nur Vorschläge machen, wenn bestehende Zuteilung schwach/problematisch ist.
In replace_all darf für alle Rollen ein Vorschlag berechnet werden, aber trotzdem nichts direkt speichern.
Pro Rolle Top 3 Alternativen berechnen.
Pro Set Piece denselben Spieler nicht doppelt vergeben, sofern sinnvoll möglich.
Verwende einen einfachen Greedy-Algorithmus.
Rollen nach Wichtigkeit sortieren:
delivery
aerial_target
defensive_marker
rest_defense
blocker
runner
rebound
counter_outlet
generic

Response:

{
  summary: {
    totalRoles: number;
    alreadyAssigned: number;
    safeSuggestions: number;
    reviewSuggestions: number;
    problemRoles: number;
    missingProfileData: number;
  };
  suggestions: Array<{
    setPieceId: string;
    setPieceTitle: string;
    roleId: string;
    roleName: string;
    roleArchetype: string;
    currentPlayerId?: string | null;
    suggestedPlayerId?: string | null;
    suggestedBackupPlayerId?: string | null;
    score: number;
    confidence: number;
    severity: 'good' | 'review' | 'problem';
    reasons: string[];
    warnings: string[];
    alternatives: Array<{
      playerId: string;
      playerName?: string;
      score: number;
      confidence: number;
      severity: 'good' | 'review' | 'problem';
      reasons: string[];
      warnings: string[];
    }>;
    keepExisting: boolean;
  }>;
}

Wichtig:
Dieser Endpoint speichert nichts. Er analysiert nur.

PRODUKT-PRINZIP

Das Ziel ist nicht ein schönerer Editor allein.

Das Ziel ist:

“Der Coach wählt seine Startelf aus. Die App erkennt automatisch, welche Spieler für welche Standardsituations-Rollen am besten passen, schützt bestehende manuelle Zuteilungen und zeigt nur die wichtigsten Entscheidungen.”

Der Matchday soll zum Entscheidungs-Cockpit werden.

Der Editor bleibt für Detailarbeit.
Der Matchday Assistant übernimmt die Denkarbeit.
