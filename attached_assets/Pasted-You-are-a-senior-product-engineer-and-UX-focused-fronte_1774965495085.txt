PART A — STEP-BASED / PHASE-BASED ANIMATION SYSTEM
==================================================

Refactor the animation model away from one global progress interpolation.

Replace it with a step-based / phase-based sequence model.

Requirements:
- actions must be assignable to steps/phases
- animation should play step-by-step, not all at once
- each step contains one or more actions
- steps should run sequentially
- each step can have a label/title
- support reordering steps
- support assigning drawn actions to a step
- playback controls:
  - previous step
  - play
  - pause
  - next step
  - reset
- support simple speed control
- support playing one step only or full sequence

Action model should be practical, not overengineered.

Suggested action model:
- id
- type
  - run
  - pass
  - cross
  - move
  - highlight
- actorRoleId
- targetRoleId optional
- shapeId / pathId optional
- stepIndex
- duration
- label optional

UI requirements:
- create a simple step/sequence UI in BottomBar or Inspector
- user must be able to:
  - create step
  - rename step
  - assign action to step
  - reorder steps
  - delete step
- do NOT build a complex video-editing timeline
- keep the UI simple and coach-friendly

Important:
This must improve real-world usability, not just add complexity.
